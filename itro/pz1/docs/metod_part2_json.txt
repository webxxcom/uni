1.4.2 Теоретичні відомості

Короткі відомості про JSON (JavaScript Object Notation): JSON – це

легкий, текстовий формат обміну даними, який легко читається людиною та

парситься машинами. Він базується на підмножині мови програмування

JavaScript.

Структура JSON-документа:

– Дані представлені у вигляді пар «ключ: значення».

– Об’єкти починаються з { і закінчуються }.

– Масиви починаються з [ і закінчуються ].

– Ключі завжди є рядками в подвійних лапках.

– Значення можуть бути рядками, числами, булевими значеннями,

об’єктами, масивами або null.

Опис структури JSON Schema

Схема JSON — це, по суті, JSON-документ, який описує інший JSON- документ. Вона складається з:

– Кореневого об'єкта: Головний об'єкт, який містить усі визначення.

Він починається з { і закінчується }. Цей об'єкт може містити такі ключові

слова як $schema, $id, title, description та type.

– Метадані ($schema, $id, title, description):

o $schema: Вказує на версію стандарту JSON Schema, яка

використовується для валідації. Це допомагає валідаторам правильно

інтерпретувати схему.

o $id: Унікальний ідентифікатор схеми. Це дозволяє посилатися на

неї з інших схем або документів.

o title та description: Додають людсько-зрозумілі метадані. Це

особливо важливо для документування та пояснення призначення схеми.

– Головний тип даних (type):

o Ключове слово type визначає, який тип даних повинен мати

кореневий JSON-документ. У нашому прикладі це object, оскільки Order є

об'єктом.

– Опис полів (properties):

o Ключове слово properties є серцем схеми. Воно містить об'єкти,

кожен з яких відповідає полю у JSON-документі, що валідується. Кожне з цих

вкладених об'єктів має власні правила:

▪ type: Визначає тип даних для конкретного поля (string, number,

integer, boolean, array, object).

▪ description: Описує призначення поля.

o Обмеження для простих типів: Залежно від типу, можна

застосовувати додаткові обмеження:

▪ string: minLength, maxLength, pattern, format.

▪ number / integer: exclusiveMinimum, exclusiveMaximum, minimum,

maximum.

▪ enum: Набір дозволених значень.

– Обов'язковість полів (required):

o Масив required перераховує імена полів, які обов'язково повинні

бути присутні у JSON-документі.

– Вкладені об'єкти (nested objects):

o Коли поле має тип object, як restaurant або payment у нашому

прикладі, його опис сам стає міні-схемою з власними properties, required та

іншими правилами. Це дозволяє створювати складні, ієрархічні структури

даних.

– Опис масивів (items):

o Коли поле має тип array, ключове слово items використовується для

опису структури кожного елемента в масиві. У нашому випадку, menuItems є

масивом, і items описує структуру кожного MenuItem всередині.

Ця структура дозволяє створювати ієрархічну і дуже детальну модель

даних, яка забезпечує строгу валідацію і гарантує, що дані, які надходять до

системи, відповідають очікуваному формату.

Ця схема включає перевірки на:

– Обов'язкові поля: Кожен об'єкт має required поля, щоб уникнути

null або порожніх значень.

– Типи даних: Кожне поле має чітко визначений тип (integer, string,

number, boolean, array).

– Мінімальні та максимальні значення: Ціни (price, totalPrice,

amount) не можуть бути від'ємними.

– Перелік дозволених значень: Статуси замовлення та оплати

обмежені певними значеннями.

– Формат дати: Дата оплати відповідає формату ISO 8601.

Слід зауважити що у JSON Schema немає прямого аналога 'token', який

би автоматично виконував дії по видаленню початкових, кінцевих та

послідовних пробільних символів підряд. Однак, можна імітувати таку

поведінку за допомогою перевірки за регулярним виразом, що забезпечується

ключовим словом pattern.

Регулярний вираз ^(?!\\s*$).+ повинен забезпечити перевірку "не

порожній рядок". Він означає:

– ^ – початок рядка.

– (?!\\s*$) – негативний перегляд вперед (negative lookahead). Ця

частина перевіряє, що рядок не складається лише з пробілів (\s*) до кінця рядка

($).

– .+ – будь-який символ (.) один або більше разів (+).

Цей вираз ефективно забороняє рядки, що складаються лише з пробілів,

або повністю порожні рядки. Він є близьким аналогом до поведінки token з

точки зору валідації.

Важливо зауважити, що на відміну від XML Schema, JSON Schema не

буде автоматично обрізати пробіли, це лише валідація. Якщо ви хочете, щоб

дані були очищені від зайвих пробілів, це потрібно робити на рівні програми,

що обробляє JSON.

Щоб посилатися на одну JSON схему з іншої, ви можете

використовувати ключове слово $ref. Це дозволяє вам повторно

використовувати схеми, роблячи ваші визначення модульними та простішими

у підтримці. Існує кілька варіанті посилання на сщему.

можете використовувати JSON Pointer:

1. Відносні шляхи: використовуйте відносні шляхи для локальних
